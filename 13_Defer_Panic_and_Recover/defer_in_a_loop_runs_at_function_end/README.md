# A `defer` in a loop runs at function end

**Level:** 301 · anyone who has hit `too many open files` in a loop that closed every file

**One line:** A deferred call runs when the *function* returns, not when the loop iteration ends, so a loop that opens a file per iteration and defers its `Close` holds every file open until the function returns; the fix is a function per iteration — a helper or a function literal — and no tool in the Go distribution flags the original.

The same file is opened 1,000 times by three loops. The first defers each `Close` in the loop body; the second calls a helper that opens, defers and returns; the third does the same in a function literal. A tracker counts opens, closes, and the most files open at once.

## Reading the output

**`closed 0 of 1000` at the end of the loop, `1000 of 1000` after the return, and 1,000 open at once.** Every one of the thousand `defer t.close(f)` statements ran — after the function returned. The [spec ↗](https://go.dev/ref/spec#Defer_statements) attaches a deferred call to the *surrounding function*, and a `for` body is not a function. Inside the loop nothing had closed; the file descriptors piled up to a thousand.

**A helper per iteration: closed as it went, at most one open.** `readOne` opens, defers, returns — and its return runs its `Close`. The loop in `aHelperPerIteration` sees each file closed before the next opens.

**A function literal per iteration: the same numbers.** `func() error { ...; defer t.close(f); ... }()` is the helper written in place and called at once. It reads worse than the helper, and it is the shape to reach for when the body needs several of the loop's variables.

**Why a thousand mattered.** A process may hold only so many open files at once — `ulimit -n` in the shell, `RLIMIT_NOFILE` to the kernel — and a loop over a directory of ten thousand files with a deferred `Close` per iteration finds the limit. Since Go 1.19 a program that imports `os` raises the soft limit to the hard limit at startup ([Go 1.19 release notes ↗](https://go.dev/doc/go1.19#os)), which is why a thousand went through here; that moves the wall, it does not remove it. The compiler also treats these defers differently — the last line of [What a `defer` costs](../deferred_calls_run_last_in_first_out/README.md#what-a-defer-costs) shows the loop's `defer` as `heap-allocated` where a plain one is `open-coded`.

```go
// A defer inside a loop does not run at the end of the iteration; it runs
// when the function returns. A loop that opens a file per iteration and
// defers its Close holds every file open until the loop's function returns.
// The fix is a function per iteration -- a helper or a function literal --
// whose own return runs the Close. The tracker counts opens and closes.
//
//	go build defer_in_a_loop_runs_at_function_end_go.go && ./defer_in_a_loop_runs_at_function_end_go
package main

import (
	"fmt"
	"os"
)

// tracker counts the files a loop opened and closed, and the most open at once.
type tracker struct{ opened, closed, openNow, mostOpen int }

func (t *tracker) open(path string) (*os.File, error) {
	f, err := os.Open(path)
	if err != nil {
		return nil, err
	}
	t.opened++
	t.openNow++
	t.mostOpen = max(t.mostOpen, t.openNow)
	return f, nil
}

func (t *tracker) close(f *os.File) {
	f.Close()
	t.closed++
	t.openNow--
}

// deferInTheLoop: every Close waits for this function to return.
func deferInTheLoop(path string, n int, t *tracker) error {
	for range n {
		f, err := t.open(path)
		if err != nil {
			return err
		}
		defer t.close(f)
	}
	fmt.Printf("  end of the loop, still inside the function: closed %d of %d\n", t.closed, t.opened)
	return nil
}

// aHelperPerIteration: readOne's return runs its Close, once per iteration.
func aHelperPerIteration(path string, n int, t *tracker) error {
	for range n {
		if err := readOne(path, t); err != nil {
			return err
		}
	}
	fmt.Printf("  end of the loop, still inside the function: closed %d of %d\n", t.closed, t.opened)
	return nil
}

func readOne(path string, t *tracker) error {
	f, err := t.open(path)
	if err != nil {
		return err
	}
	defer t.close(f)
	return nil
}

// aLiteralPerIteration: the same, with the helper written in place.
func aLiteralPerIteration(path string, n int, t *tracker) error {
	for range n {
		err := func() error {
			f, err := t.open(path)
			if err != nil {
				return err
			}
			defer t.close(f)
			return nil
		}()
		if err != nil {
			return err
		}
	}
	fmt.Printf("  end of the loop, still inside the function: closed %d of %d\n", t.closed, t.opened)
	return nil
}

func main() {
	orders, err := os.CreateTemp("", "orders-*.csv")
	if err != nil {
		panic(err)
	}
	orders.Close()
	defer os.Remove(orders.Name())

	const n = 1000
	loops := []struct {
		name string
		run  func(string, int, *tracker) error
	}{
		{"defer in the loop", deferInTheLoop},
		{"a helper per iteration", aHelperPerIteration},
		{"a function literal per iteration", aLiteralPerIteration},
	}
	for _, loop := range loops {
		fmt.Printf("%s, %d opens:\n", loop.name, n)
		var t tracker
		if err := loop.run(orders.Name(), n, &t); err != nil {
			panic(err)
		}
		fmt.Printf("  after the function returned: closed %d of %d, most open at once: %d\n", t.closed, t.opened, t.mostOpen)
	}
}
```

## What to do

- **Move the loop body into a function** when it opens, locks or acquires anything: `for _, path := range paths { if err := process(path); err != nil { return err } }`, with the `defer` inside `process`.
- **Use a function literal** when the body needs several of the loop's variables and a helper would take too many parameters; call it on the spot.
- **Or close explicitly** at the end of the body, if nothing between the open and the close can return or panic — and be honest about that "nothing".
- **Keep the `defer` in the loop only when you want them all at function end**: an undo stack, as in the kata of [Deferred calls run last in, first out](../deferred_calls_run_last_in_first_out/README.md).

```go
// Kata: add up the boxes in five shipment files, reading each file in a
// helper whose deferred Close runs when the helper returns, and prove that
// no more than one file was ever open at once.
package main

import (
	"fmt"
	"os"
	"path/filepath"
	"strconv"
)

var open, mostOpen int

// openCounted is os.Open with a count of the files open right now.
func openCounted(path string) (*os.File, error) {
	f, err := os.Open(path)
	if err == nil {
		open++
		mostOpen = max(mostOpen, open)
	}
	return f, err
}

func closeCounted(f *os.File) {
	f.Close()
	open--
}

// boxesIn reads one shipment file; its Close runs when boxesIn returns.
func boxesIn(path string) (int, error) {
	f, err := openCounted(path)
	if err != nil {
		return 0, err
	}
	defer closeCounted(f)
	var boxes int
	_, err = fmt.Fscan(f, &boxes)
	return boxes, err
}

func main() {
	dir, err := os.MkdirTemp("", "shipments")
	if err != nil {
		panic(err)
	}
	defer os.RemoveAll(dir)

	var paths []string
	for i := 1; i <= 5; i++ {
		path := filepath.Join(dir, "shipment-"+strconv.Itoa(i)+".txt")
		if err := os.WriteFile(path, []byte(strconv.Itoa(i*2)+"\n"), 0o644); err != nil {
			panic(err)
		}
		paths = append(paths, path)
	}

	total := 0
	for _, path := range paths {
		boxes, err := boxesIn(path)
		if err != nil {
			panic(err)
		}
		total += boxes
	}
	fmt.Printf("shipments: %d, boxes: %d, most open at once: %d, still open: %d\n", len(paths), total, mostOpen, open)
}
```

## In other languages

- **Rust** has no such trap: a `File` bound inside a loop body is dropped at the end of each iteration, because the body's block is a scope — the Rust library's [Scope is about names, not values ↗](https://masiarek.github.io/rust-learning-library/18_Ownership/scope_is_about_names/index.html).
- **Python**'s `with open(path) as f:` inside a loop closes the file when the `with` block ends, every iteration ([the `with` statement ↗](https://docs.python.org/3/reference/compound_stmts.html#the-with-statement)); a `try`/`finally` inside the body does the same.
- **C++** destroys a `std::ifstream` declared in the loop body at the end of each iteration; the block, not the function, is the scope ([RAII ↗](https://en.cppreference.com/w/cpp/language/raii)).

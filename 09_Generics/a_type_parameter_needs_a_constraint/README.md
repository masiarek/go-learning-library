# A type parameter needs a constraint

**Level:** 201 · anyone who wrote `[T any]` and then could not add two of them

**One line:** A type parameter can do only what every type in its constraint's set can do — under `any` that is store and pass on, nothing more; `cmp.Ordered` unlocks `<` and `>`, `comparable` unlocks `==`, and a `~int` term admits every type whose underlying type is `int` — which is why a `Sum` over a `Number` built from `~` terms takes a `[]Celsius` and the same union without `~` does not.

Three functions, each with the constraint that grants what its body does: `Max` needs `>`, so it is constrained by `cmp.Ordered`; `Sum` needs `+` and a zero value, so it is constrained by a `Number` interface written from `~` terms; `Contains` needs `==`, so it is constrained by `comparable`. `Celsius` is a named type with underlying type `float64`, and it goes through two of them.

## Reading the output

**`Max` orders ints, strings and a `Celsius`.** [`cmp.Ordered` ↗](https://pkg.go.dev/cmp#Ordered) is itself a constraint written from `~` terms: every integer type, every float type and `~string`. `Celsius` is in that set because its underlying type is `float64`, so `Max(Celsius(21), Celsius(19))` compiles and returns a `Celsius`. The [spec ↗](https://go.dev/ref/spec#Operators) allows an operator on a type parameter only when it is defined for every type in the type set — the compiler does not look at which types you happen to call with.

**`Max` and NaN.** `Max(2.5, NaN)` is `NaN` and `Max(NaN, 2.5)` is `2.5`: `a > b` is false whenever either side is NaN, so this `Max` returns whichever argument sits in `b`. The builtin `max` returns NaN if any argument is NaN ([spec ↗](https://go.dev/ref/spec#Min_and_max)), and [`cmp.Compare` ↗](https://pkg.go.dev/cmp#Compare) orders a NaN below everything. A `cmp.Ordered` function has a decision to make about floats that an `int` one never had.

**`Sum` adds a `[]Celsius`.** `Number` is `~int | ~int64 | ~float64`. The [spec ↗](https://go.dev/ref/spec#General_interfaces) defines `~T` as the set of all types whose underlying type is `T`, and `Celsius`'s [underlying type ↗](https://go.dev/ref/spec#Underlying_types) is `float64`. `var total T` is the zero value of whichever type was chosen — `0`, `0.0` or `Celsius(0)`.

**`Contains` compares with `==`.** `comparable` is a [predeclared ↗](https://go.dev/ref/spec#Predeclared_identifiers) constraint: the types that support `==` and `!=`. It is the constraint a map key needs, which is why [A generic type and its zero value](../a_generic_type_and_its_zero_value/README.md) builds its `Set` on `comparable` and not `any`.

## What `any` allows

`any` is the empty interface, and as a constraint its type set is every type — so the function may do only what every type supports. The same three functions with `any` in place of their constraints:

Three refusals, three wordings, one rule. `>` is not defined for every type in the set (a struct has no ordering), `+` is not defined for every type, and `==` is not defined for every type (a slice has no `==`). Only the `+` message spells out `constrained by any`; the other two name the operator or the type set. All three are compile errors, before any call exists: a generic function is checked once, against its constraint, not once per instantiation.

The compiler's parenthesis is the fix. `SumLoose`, constrained by `~int | ~float64`, took the same `[]Celsius` on the line before and was not reported. A union that lists predeclared types without `~` will work for every caller who passes `int` and `float64` and fail for the first one who defined a `type Celsius float64` — and that caller may be in another package, months later. Nothing before that compile error warns you: [what go vet and gofmt catch](../generics_vet_and_lints/README.md) lists it under what no tool catches.

```go
// A type parameter is only as capable as its constraint. Under any, a T can be
// stored and passed on and nothing more; cmp.Ordered unlocks < and >,
// comparable unlocks ==, and a ~int term admits every type whose underlying
// type is int, not just int itself.
//
//	go build a_type_parameter_needs_a_constraint_go.go && ./a_type_parameter_needs_a_constraint_go
package main

import (
	"cmp"
	"fmt"
	"math"
)

// Max needs >, so its constraint is cmp.Ordered: every integer, float and
// string type, and every named type built on one of them.
func Max[T cmp.Ordered](a, b T) T {
	if a > b {
		return a
	}
	return b
}

// Number is a type set written with ~ terms: int, int64, float64, and every
// named type whose underlying type is one of them.
type Number interface {
	~int | ~int64 | ~float64
}

// Sum needs + and a zero value of T. Both come from Number: every type in the
// set has them.
func Sum[T Number](values []T) T {
	var total T
	for _, v := range values {
		total += v
	}
	return total
}

// Contains needs ==, which comparable provides.
func Contains[T comparable](values []T, want T) bool {
	for _, v := range values {
		if v == want {
			return true
		}
	}
	return false
}

// Celsius is a named type whose underlying type is float64. Number admits it
// because its terms carry ~; cmp.Ordered admits it for the same reason.
type Celsius float64

func main() {
	fmt.Println("Max(3, 7) =", Max(3, 7))
	fmt.Println("Max(\"pear\", \"apple\") =", Max("pear", "apple"))
	fmt.Println("Max(Celsius(21), Celsius(19)) =", Max(Celsius(21), Celsius(19)))
	fmt.Println("Max(2.5, NaN) =", Max(2.5, math.NaN()), " Max(NaN, 2.5) =", Max(math.NaN(), 2.5), " builtin max(2.5, NaN) =", max(2.5, math.NaN()))

	fmt.Println("Sum([]int{1, 2, 3}) =", Sum([]int{1, 2, 3}))
	fmt.Println("Sum([]float64{0.5, 0.25}) =", Sum([]float64{0.5, 0.25}))
	fmt.Println("Sum([]Celsius{21.5, 19}) =", Sum([]Celsius{21.5, 19}))

	fmt.Println("Contains(readings, 19) =", Contains([]int{21, 19, 23}, 19))
	fmt.Println("Contains(names, \"kiwi\") =", Contains([]string{"pear", "apple"}, "kiwi"))
}
```

```bash
#!/usr/bin/env bash
# Under the constraint any, a type parameter T admits every type -- so the
# compiler lets the function do only what every type can do. >, + and == are
# each refused, and each refusal is worded differently.
set -u
export GOTOOLCHAIN=local

dir=$(mktemp -d)
trap 'rm -rf "$dir"' EXIT

cat >"$dir/under_any.go" <<'GO'
package main

func Max[T any](a, b T) T {
	if a > b {
		return a
	}
	return b
}

func Sum[T any](values []T) T {
	var total T
	for _, v := range values {
		total = total + v
	}
	return total
}

func Contains[T any](values []T, want T) bool {
	for _, v := range values {
		if v == want {
			return true
		}
	}
	return false
}

func main() {}
GO

say() { printf '$ %s\n' "$*"; }

say 'go build under_any.go'
(cd "$dir" && go build under_any.go) 2>&1
echo "exit status $?"
```

## What to do

- **Constrain for what the body does.** `<` needs `cmp.Ordered`; `==` needs `comparable`; `+` on numbers needs a union of number types; a method call needs an interface with that method. `any` is right only for a function that stores, passes or counts its `T` — a `Map`, a `Filter`, a `Stack`.
- **Write union terms with `~`** unless you mean exactly those predeclared types and no named type built on them. `cmp.Ordered` and the constraints in the [Go blog's introduction ↗](https://go.dev/blog/intro-generics) are all written that way.
- **Reach for `cmp.Ordered` and `comparable` before writing your own**, and for [`slices` ↗](https://pkg.go.dev/slices) and [`maps` ↗](https://pkg.go.dev/maps) before writing a `Contains` or a `Max` at all: `slices.Contains`, `slices.Max` and `slices.Index` are those functions with those constraints.
- **Decide what a float `Max` does with NaN**, and say so in its doc comment; `cmp.Compare` and the builtin `max` made two different choices.

## Practice

Write `Average[T Number](values []T) float64`, which returns the mean as a `float64` whatever `T` is (convert each value with `float64(v)` — allowed because every type in `Number`'s set converts), and `MinMax[T cmp.Ordered](values []T) (lo, hi T)`, which returns two values of the caller's type. Call `Average` on a `[]int` and on a `[]Celsius`, and `MinMax` on a `[]string` and a `[]Celsius`; print the results with `%T` on one of the `Celsius` results to show that the type came back unchanged.

```go
// Kata: an Average over a Number constraint, returning float64 whatever T is,
// and a MinMax over cmp.Ordered -- each called on a named type as well as a
// predeclared one.
//
//	go build a_type_parameter_needs_a_constraint_kata_go.go && ./a_type_parameter_needs_a_constraint_kata_go
package main

import (
	"cmp"
	"fmt"
)

type Number interface {
	~int | ~int64 | ~float64
}

// Average converts each value: float64(v) is allowed because every type in
// Number's set converts to float64.
func Average[T Number](values []T) float64 {
	if len(values) == 0 {
		return 0
	}
	var total float64
	for _, v := range values {
		total += float64(v)
	}
	return total / float64(len(values))
}

// MinMax needs < and >, so cmp.Ordered; it returns two values of T, not of
// float64, because the caller's type is the one that carries meaning.
func MinMax[T cmp.Ordered](values []T) (lo, hi T) {
	lo, hi = values[0], values[0]
	for _, v := range values[1:] {
		if v < lo {
			lo = v
		}
		if v > hi {
			hi = v
		}
	}
	return lo, hi
}

type Celsius float64

func main() {
	fmt.Println("Average of quantities:", Average([]int{4, 7, 10}))
	fmt.Println("Average of readings:  ", Average([]Celsius{21.5, 19, 23}))
	lo, hi := MinMax([]string{"pear", "apple", "quince"})
	fmt.Printf("MinMax of names:       %q %q\n", lo, hi)
	rlo, rhi := MinMax([]Celsius{21.5, 19, 23})
	fmt.Printf("MinMax of readings:    %v %v (%T)\n", rlo, rhi, rlo)
}
```

## In other languages

- **Rust** — [Where the bound goes ↗](https://masiarek.github.io/rust-learning-library/22_Generics/where_the_bound_goes/index.html) states the same rule: an unbounded `T` can be stored, moved and dropped, and a trait bound buys the rest. Rust spells the bound as a trait (`T: PartialOrd`), Go as an interface read as a type set. In Rust [operators are traits ↗](https://masiarek.github.io/rust-learning-library/12_Traits/operators_are_traits/index.html), so a user struct can implement `Add` and satisfy a `T: Add` bound; Go has no operator methods, so `+` on a `T` exists only when every type in the set is one that already has it — which is why `Number` is a union of number types and can never admit a struct.
- **C++** — a template parameter had no constraint at all before C++20 [concepts ↗](https://en.cppreference.com/w/cpp/language/constraints): `a > b` on an unconstrained `T` compiles until some instantiation lacks `>`, and the error appears then, inside the template. Go checks the generic function once, against its constraint, before any instantiation exists.
- **C** — no generics: [`qsort` ↗](https://en.cppreference.com/w/c/algorithm/qsort) takes a `void *`, an element size and a comparison function, and the compiler checks none of the three against each other.

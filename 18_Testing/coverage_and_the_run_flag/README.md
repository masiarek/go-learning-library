# Coverage and the flags that choose tests

**Level:** 201 · anyone who runs `go test ./...` and reads only the last line

**One line:** `go test -cover` prints the share of statements the tests executed — exact for fixed code and fixed tests — and `go tool cover -func` breaks it down per function; `-run` and `-skip` match a regular expression per `/`-separated level of a test's name; `(cached)` appears only when `go test` is given a package argument, and `-count=1` switches it off; `-shuffle=on` prints a seed that changes every run, and `-shuffle=1` repeats one order; `testing.Short()` reports `-short`.

`ParseQuantity` and `Plural` are tested by two cases at first, and by four after a second test file is added. The driver records the percentage, the per-function table, the first lines of the profile, and the percentage again.

## Reading the output

**`coverage: 60.0% of statements`** — of the ten statements in the package, the two cases executed six: `Plural` was never called, and `ParseQuantity`'s `strconv.Atoi` error branch never taken. The figure is a property of the code and the tests, not of the run, so it is a key; the Docker check found the same 60.0% on Linux. In local directory mode, plain `go test`, the line stands on its own; with a package argument, `go test -cover .`, it is appended to the `ok` line (measured, not shown).

**`go tool cover -func` names the functions.** `ParseQuantity 85.7%` and `Plural 0.0%`, then `total: (statements) 60.0%`. The profile itself, `cover.out`, is a list of blocks — file, start line and column, end line and column, the number of statements, and how many times the block ran — under a `mode:` line; `set` records whether a block ran, `count` how often, and `atomic` counts safely under `-race` ([`cmd/cover` ↗](https://pkg.go.dev/cmd/cover)). `go tool cover -html=cover.out` paints the source from the same file.

**Coverage is a map of what was not tested, not a score.** `100.0% of statements` after `more_test.go` says only that every statement ran. A `TestPlural` that called `Plural` and compared nothing would produce the same figure — the first bullet of [What no tool catches](../testing_vet_and_lints/README.md#what-no-tool-catches). [*The cover story* ↗](https://go.dev/blog/cover) ends on the same caution.

**`-run TestParse`** matches the top-level names that contain `TestParse` — both `TestParseQuantity` and `TestParseUnit`, with all of their subtests — and not `TestTotal`. Patterns are unanchored regular expressions ([Testing flags ↗](https://pkg.go.dev/cmd/go#hdr-Testing_flags)).

**`-run '/empty'`** has an empty first element, which matches every top-level test; the second element selects subtests called `empty`. `TestTotal` ran too: it has no subtests for the second element to exclude, and `go help testflag` says that possible parents of matches are run so that their subtests can be looked for. Anchor the elements to be exact: `'TestParseQuantity/^(crates|negative)$'`.

**`-skip '/empty'`** removes those subtests and keeps everything else; `-skip` was added in Go 1.20 ([release notes ↗](https://go.dev/doc/go1.20#go-command)). **`-skip 'empty'`**, with no slash, is matched against the top level only — no test is called `empty` — and skipped nothing. That silent no-op is the mistake to know about: a pattern that never matches is not an error.

**`-run TestInvoice`: `no tests to run`, exit 0.** A `-run` that selects nothing is a warning on the first line of the output, and the package still reports `ok`. A CI job that misspells a test name goes green.

## `-count=1`, the cache, and `-failfast`

<!-- output:coverage_count_and_the_cache_sh -->
*Verified output of [`coverage_count_and_the_cache_sh.sh`](examples/coverage_count_and_the_cache_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go mod init example
$ go test .
ok  	example
exit status 0
$ go test .     # the same package, the same tests: served from the cache
ok  	example	(cached)
exit status 0
$ go test -count=1 .
ok  	example
exit status 0
$ go test          # local directory mode: never cached
PASS
ok  	example
exit status 0
$ go test -v -run Fails
=== RUN   TestFirstFails
--- FAIL: TestFirstFails
=== RUN   TestSecondFails
--- FAIL: TestSecondFails
FAIL
FAIL	example
exit status 1
$ go test -v -failfast -run Fails
=== RUN   TestFirstFails
--- FAIL: TestFirstFails
FAIL
FAIL	example
exit status 1
```
<!-- /output -->

**`(cached)` on the second `go test .`.** In package list mode — any `go test` with a package argument, `.` or `./...` — a passing result is cached, keyed on the test binary and the flags, and the next identical run prints `(cached)` in place of a time ([`go help test`, caching ↗](https://pkg.go.dev/cmd/go#hdr-Test_packages)). Only a short list of flags is cacheable — `-run`, `-v`, `-short`, `-failfast`, `-cpu`, `-parallel` and a few more — and `-count` is not on it, so `-count=1` forces a real run, and so would `-count=100`. Plain `go test`, local directory mode, never caches, which is why the fourth line shows `PASS` and `ok` with no `(cached)`. The cache also watches the files and environment variables a test reads, so a test that opens `testdata/` is rerun when that changes.

**`-failfast` stops at the first failure.** Two failing tests without it, one with it. It stops the *package's* tests after the first failure; other packages still run.

**`-shuffle=1` prints `-test.shuffle 1` and one order; `-shuffle=7` another.** The seed drives a `math/rand` source, whose sequence is fixed for a fixed seed, so a seed reproduces an order on any machine ([Go 1.17 release notes ↗](https://go.dev/doc/go1.17#go-command)). `-shuffle=on` picks the time in nanoseconds as the seed and prints it, so that a failure can be reproduced with `-shuffle=<that seed>`:

```text title="Real runs — go1.25.5, x86-64 Mac, 5 runs of go test -shuffle=on, 2026-09-23"
1790206819370744000: TestCrates TestBins TestPallets
1790206821056712000: TestPallets TestCrates TestBins
1790206823458345000: TestCrates TestBins TestPallets
1790206825682666000: TestPallets TestBins TestCrates
1790206827537114000: TestBins TestCrates TestPallets
```

Five runs, five seeds, four orders — `bash demo/shuffle_seeds.sh` from this folder repeats it. A test that passes in source order and fails under some seed depends on a test before it; the seed is the way to find which.

**`-short` is a flag the test reads.** `testing.Short()` is true when `-short` was given, and nothing else changes: the test itself must call `t.Skip`, and then it is reported as `--- SKIP` with the reason, and the package is still `ok` ([`testing.Short` ↗](https://pkg.go.dev/testing#Short)). Without `-short` the full import runs.

**`-json`.** `go test -json` prints one JSON event per line — `run`, `output`, `pass`, `fail`, with the package and test names and a timestamp — for tooling to read ([`cmd/test2json` ↗](https://pkg.go.dev/cmd/test2json)); the timestamps keep it out of these keys.

#!/usr/bin/env bash
# go test -cover prints the share of statements the tests ran, and
# -coverprofile plus go tool cover -func breaks it down per function. Both
# are fixed for fixed code and fixed tests, so they are the key. A third test
# case reaches the last untested branch and the figure rises to 100%.

// Package stock parses the quantities on a delivery note.
package stock

import (
	"errors"
	"strconv"
	"strings"
)

// ParseQuantity reads "12 crates" into its number and its unit.
func ParseQuantity(s string) (int, string, error) {
	fields := strings.Fields(s)
	if len(fields) != 2 {
		return 0, "", errors.New("want a number and a unit")
	}
	n, err := strconv.Atoi(fields[0])
	if err != nil {
		return 0, "", err
	}
	return n, fields[1], nil
}

// Plural returns the unit's plural for a count.
func Plural(n int, unit string) string {
	if n == 1 {
		return unit
	}
	return unit + "s"
}
GO

cat >quantity_test.go <<'GO'
package stock

import "testing"

func TestParseQuantity(t *testing.T) {
	cases := []struct {
		name, in string
		n        int
		unit     string
		wantErr  bool
	}{
		{"crates", "12 crates", 12, "crates", false},
		{"empty", "", 0, "", true},
	}
	for _, c := range cases {
		t.Run(c.name, func(t *testing.T) {
			n, unit, err := ParseQuantity(c.in)
			if (err != nil) != c.wantErr {
				t.Fatalf("ParseQuantity(%q): err = %v, want an error: %t", c.in, err, c.wantErr)
			}
			if n != c.n || unit != c.unit {
				t.Errorf("ParseQuantity(%q) = %d, %q; want %d, %q", c.in, n, unit, c.n, c.unit)
			}
		})
	}
}
GO

say() { printf '$ %s\n' "$*"; }

tidy() {
	sed -E 's/ \([0-9.]+s\)$//; s/^(ok|FAIL)([[:space:]]+example)[[:space:]]+[0-9.]+s$/\1\2/' test.txt
}

say 'go mod init example'
go mod init example 2>/dev/null || exit 1

say 'go test -cover'
go test -cover >test.txt 2>&1
status=$?
tidy
echo "exit status $status"

say 'go test -coverprofile=cover.out >/dev/null && go tool cover -func=cover.out'
go test -coverprofile=cover.out >/dev/null 2>&1 && go tool cover -func=cover.out
echo "exit status $?"

say 'head -n 3 cover.out'
head -n 3 cover.out

package stock

import "testing"

func TestParseQuantityNotANumber(t *testing.T) {
	if _, _, err := ParseQuantity("many crates"); err == nil {
		t.Error("want an error for a quantity that is not a number")
	}
}

func TestPlural(t *testing.T) {
	if got := Plural(1, "crate"); got != "crate" {
		t.Errorf("Plural(1) = %q", got)
	}
	if got := Plural(3, "crate"); got != "crates" {
		t.Errorf("Plural(3) = %q", got)
	}
}
GO

## What to do

- **Read `go tool cover -func` for the functions at 0%**, not the total for a number to raise. A function nobody calls in a test is either untested or dead.
- **`-run 'TestName/^case$'` while fixing one case, and check the `=== RUN` lines once** — a pattern that matches nothing is a warning and exit 0, not a failure.
- **`-count=1` when the result must be fresh** — after changing an environment variable or a file the test does not open itself — and `go test .` or `./...` the rest of the time, so that the cache does its work.
- **Run `-shuffle=on` in CI and keep the seed from a failing run**; reproduce with `-shuffle=<seed>`.
- **Guard slow tests with `testing.Short()` and run `go test -short` locally**, with the full suite in CI — and never guard the only test of a package, which makes `-short` a run of nothing.

	run(dir, "go", "mod", "init", "example")

	coverage(dir)
	fmt.Println("$ cat >more_test.go   # the case that reaches the Atoi error branch")
	must(os.WriteFile(filepath.Join(dir, "more_test.go"), []byte(moreTest), 0o644))
	coverage(dir)
}

// coverage records a profile and prints the per-function table.
func coverage(dir string) {
	run(dir, "go", "test", "-coverprofile=cover.out")
	fmt.Println("$ go tool cover -func=cover.out")
	cmd := exec.Command("go", "tool", "cover", "-func=cover.out")
	cmd.Dir = dir
	out, err := cmd.CombinedOutput()
	fmt.Print(string(out))
	must(err)
}

// run runs a command whose output is not part of the key.
func run(dir string, name string, args ...string) {
	cmd := exec.Command(name, args...)
	cmd.Dir = dir
	if out, err := cmd.CombinedOutput(); err != nil {
		panic(string(out))
	}
}

func must(err error) {
	if err != nil {
		panic(err)
	}
}

## In other languages

- The Rust library's [How `cargo test` runs your tests ↗](https://masiarek.github.io/rust-learning-library/28_Testing/how_cargo_test_runs/index.html) — `cargo test name` filters by substring and `--skip` removes, with no per-level `/`; `--test-threads=1` fixes an order where Go has `-shuffle` to unfix one; coverage is not in `cargo` at all and needs `cargo-llvm-cov` or `tarpaulin`.
- Python's [`unittest` command line ↗](https://docs.python.org/3/library/unittest.html#command-line-interface) has `-k` for a substring pattern and `-f` for fail-fast; coverage is the separate [`coverage.py` ↗](https://coverage.readthedocs.io/), which reports per file and per line rather than per function.

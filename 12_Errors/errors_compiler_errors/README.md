# Errors: the compiler errors

**Level:** 201 · anyone reading a refusal from `go build` that mentions `err`

**One line:** Seven refusals the compiler gives around error values — an `err` that is received and never read, a function that forgets its success return, an interface assigned to a concrete type, the `pkg/errors` names, a string where an error is wanted, `errors.New` with format arguments, and an `Error` method with the wrong signature — each recorded in the Go 1.25 compiler's own words. `%w` in the wrong `fmt` function compiles; that one is `go vet`'s, in [Errors: what go vet and gofmt catch](../errors_vet_and_lints/README.md).

Each transcript is a bash driver that writes the broken program, runs `go build` on it and prints the output and the exit status. Positions like `./unused_err.go:6:10:` are stable because the program is fixed; the wording is this compiler's, and a later release may change it — which is why it is recorded rather than typed.

## declared and not used: err

Opening a file, receiving the error, and going straight on to use the file.

<!-- output:errors_err_declared_not_used_sh -->
*Verified output of [`errors_err_declared_not_used_sh.sh`](examples/errors_err_declared_not_used_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build unused_err.go
# command-line-arguments
./unused_err.go:6:10: declared and not used: err
exit status 1
```
<!-- /output -->

**The mistake.** `err` was assigned and never read. Go has no warning level for this: an unused local variable is a compile error, and an unused error result is the case the rule exists for.

**The fix.** Check it, on the next line, before touching what came with it:

```go
orders, err := os.Open("orders.csv")
if err != nil {
	return fmt.Errorf("open orders: %w", err)
}
defer orders.Close()
```

## missing return

The failure path returns, the success path prints and falls off the end.

<!-- output:errors_err_missing_return_sh -->
*Verified output of [`errors_err_missing_return_sh.sh`](examples/errors_err_missing_return_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build missing_return.go
# command-line-arguments
./missing_return.go:14:1: missing return
exit status 1
```
<!-- /output -->

**The mistake.** A function with results must end in a terminating statement, and an `if` without an `else` is not one, whatever its body returns ([spec ↗](https://go.dev/ref/spec#Terminating_statements)). The compiler points at the closing brace.

**The fix.** Return the success value after the check — the `if err != nil { return }` shape leaves the happy path at the left margin on purpose:

```go
if err != nil {
	return 0, fmt.Errorf("size of %s: %w", name, err)
}
return info.Size(), nil
```

## cannot use err (variable of interface type error) as *NotFoundError value

Assigning an `error` to a variable of the concrete type it is expected to hold.

<!-- output:errors_err_need_type_assertion_sh -->
*Verified output of [`errors_err_need_type_assertion_sh.sh`](examples/errors_err_need_type_assertion_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build need_assertion.go
# command-line-arguments
./need_assertion.go:13:26: cannot use err (variable of interface type error) as *NotFoundError value in variable declaration: need type assertion
exit status 1
```
<!-- /output -->

**The mistake.** An interface value does not convert down by itself; the compiler says what it wants — a type assertion. And the assertion only looks at the outer layer, so if `err` was ever wrapped it will fail at run time instead.

**The fix.** `errors.As` is the assertion that also searches the chain — [`errors.As` finds a type in the chain](../errors_as_finds_a_type_in_the_chain/README.md):

```go
var nf *NotFoundError
if errors.As(err, &nf) {
	fmt.Println(nf.ID)
}
```

## undefined: errors.Wrap

Writing `errors.Wrap` and `errors.Cause` from memory of the `github.com/pkg/errors` package, with the standard `errors` imported.

<!-- output:errors_err_undefined_wrap_sh -->
*Verified output of [`errors_err_undefined_wrap_sh.sh`](examples/errors_err_undefined_wrap_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build pkg_errors_habit.go
# command-line-arguments
./pkg_errors_habit.go:12:22: undefined: errors.Wrap
./pkg_errors_habit.go:13:22: undefined: errors.Cause
exit status 1
```
<!-- /output -->

**The mistake.** The standard package never had `Wrap` or `Cause`. Since Go 1.13 the wrap is `fmt.Errorf` with `%w`, and the walk is `errors.Is`, `errors.As` and `errors.Unwrap`; [`pkg/errors` ↗](https://github.com/pkg/errors) is in maintenance mode and its README says so.

**The fix.**

```go
return fmt.Errorf("load orders: %w", err)   // errors.Wrap(err, "load orders")
root := err
for errors.Unwrap(root) != nil {            // errors.Cause(err)
	root = errors.Unwrap(root)
}
```

## string does not implement error

Comparing an error with its text — once by handing the text to `errors.Is`, once with `err.Error` and no parentheses.

<!-- output:errors_err_not_an_error_sh -->
*Verified output of [`errors_err_not_an_error_sh.sh`](examples/errors_err_not_an_error_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build text_is_not_an_error.go
# command-line-arguments
./text_is_not_an_error.go:12:20: cannot use "order not found" (constant of type string) as error value in argument to errors.Is: string does not implement error (missing method Error)
./text_is_not_an_error.go:15:18: invalid operation: err.Error == "order not found" (mismatched types func() string and untyped string)
exit status 1
```
<!-- /output -->

**The mistake.** A string is not an error: it has no `Error` method, so it cannot be the second argument of `errors.Is`. And `err.Error` without the call is a method value of type `func() string`, which is not comparable with a string either. Both are symptoms of the same idea — matching on the message — which also breaks the moment someone rewords it.

**The fix.** Compare with the sentinel, through the chain — [`%w` wraps and `errors.Is` sees through it](../wrap_with_w_unwrap_with_is/README.md):

```go
if errors.Is(err, ErrNotFound) {
```

## too many arguments in call to errors.New

Giving `errors.New` a format verb and an argument, the way `fmt.Errorf` takes them.

<!-- output:errors_err_new_too_many_args_sh -->
*Verified output of [`errors_err_new_too_many_args_sh.sh`](examples/errors_err_new_too_many_args_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build new_with_args.go
# command-line-arguments
./new_with_args.go:7:42: too many arguments in call to errors.New
	have (string, int)
	want (string)
exit status 1
```
<!-- /output -->

**The mistake.** `errors.New` takes one string and does no formatting; the `have`/`want` lines show the signature.

**The fix.** `errors.New` for a fixed message — usually a sentinel at package level — and `fmt.Errorf` for one built from values:

```go
var ErrNotFound = errors.New("order not found")
err := fmt.Errorf("order %d: %w", id, ErrNotFound)
```

## wrong type for method Error

A type whose `Error` method returns an `error` instead of a `string`, returned where an `error` is expected.

<!-- output:errors_err_wrong_error_signature_sh -->
*Verified output of [`errors_err_wrong_error_signature_sh.sh`](examples/errors_err_wrong_error_signature_sh.sh) — regenerated by `tools/run_examples.py`, never hand-typed.*

```text
$ go build wrong_signature.go
# command-line-arguments
./wrong_signature.go:11:10: cannot use QuotaError{…} (value of struct type QuotaError) as error value in return statement: QuotaError does not implement error (wrong type for method Error)
		have Error() error
		want Error() string
exit status 1
```
<!-- /output -->

**The mistake.** The `error` interface is `Error() string` and nothing else ([spec ↗](https://go.dev/ref/spec#Errors)); a method with the same name and a different signature does not count, and the compiler prints the signature it has and the one it wants.

**The fix.**

```go
func (e QuotaError) Error() string { return fmt.Sprintf("quota of %d exceeded", e.Limit) }
```

# a string, so == refuses that too.
set -u

	"errors"
	"fmt"
)

var ErrNotFound = errors.New("order not found")

func main() {
	err := fmt.Errorf("load order 7: %w", ErrNotFound)
	if errors.Is(err, "order not found") {
		fmt.Println("not found")
	}
	if err.Error == "order not found" {
		fmt.Println("not found")
	}
}
GO

say() { printf '$ %s\n' "$*"; }

say 'go build text_is_not_an_error.go'
(cd "$dir" && go build text_is_not_an_error.go) 2>&1

## What compiles anyway

A second `err :=` inside an `if` block, shadowing the outer `err` so that the function returns nil after a failure, is legal Go and the compiler says nothing. So is `%w` handed to `Sprintf`, a typed nil returned as an `error`, and `==` on a wrapped sentinel. Those are on [Errors: what go vet and gofmt catch](../errors_vet_and_lints/README.md) — the first two under the analyzers that do report them, the rest under what no tool catches.

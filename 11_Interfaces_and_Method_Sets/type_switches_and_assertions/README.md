# A type assertion asks the dynamic type

**Level:** 201 · anyone who has an `any` and needs the value back out

**One line:** `x.(T)` asks whether the value inside `x` has type `T` — or, when `T` is an interface, whether the value's type has `T`'s methods — and the answer comes at run time: the two-value form says `ok`, the one-value form panics with `interface conversion: interface {} is string, not int`, and a type switch asks the same question once per case, binding a variable of the case's type in a one-type case and of the interface's type otherwise.

`describe` is one type switch with a `nil` case, a one-type case, a several-types case, two interface cases and a `default`; for each it also prints the *static* type the compiler gave the bound variable. Then `main` runs the assertions one by one, recovering the panics.

## Reading the output

**A one-type case binds a variable of that type; a several-types case keeps the interface.** `case int:` made `x` an `int` — its static type printed as `int` and `%d` worked on it. `case int8, int16, int32, int64:` made `x` an `interface {}` — the [spec ↗](https://go.dev/ref/spec#Type_switches) says that in a clause with exactly one type the variable has that type, and otherwise it has the type of the expression being switched on. The `default` clause is the same: `main.Order` printed through `%T`, but `x` there is an `interface {}`. (`interface {}` is how `reflect` and the runtime spell `any`.)

**`case nil` catches the nil interface.** With no such case, a nil `any` falls through to `default` — and there, `x` is a nil interface too, so anything that calls a method on it panics.

**A case that names an interface checks the method set.** `Invoice{ID: 3}` went to `case fmt.Stringer`, because `Invoice` has `String`; the variable's static type is `fmt.Stringer`, and `x.String()` compiled. `errors.New("late")` went to `case error`. Cases are tried in order, so a type that satisfied both would take the first — the spec's rule for type switches as for ordinary ones.

**Two values: the answer and `ok`.** `x.(string)` returned `"order-17", true`; `x.(int)` returned `0, false` — the zero value of `int`, not garbage, and no panic. This is the form for anything that might not be there.

**One value: the runtime's exact words.** `x.(int)` on a string panics with `interface conversion: interface {} is string, not int`. The message is built in [`error.go` ↗](https://github.com/golang/go/blob/go1.25.5/src/runtime/error.go) by `TypeAssertionError`, and its second form appears on the next line: asserting a nil interface gives `interface {} is nil, not int`.

**Asserting to another interface is a method-set question.** `order.(fmt.Stringer)` for an `Order` without a `String` method is `false` in two-value form, and in one-value form the third wording: `main.Order is not fmt.Stringer: missing method String`. The runtime looked up `Order`'s method table for `String` and did not find it — the check of [A pointer receiver changes the method set](../a_pointer_receiver_changes_the_method_set/README.md), performed at run time.

**No automatic `&` or `*`.** A `fmt.Stringer` holding an `Invoice` value, asserted to `*Invoice`, panics: `fmt.Stringer is main.Invoice, not *main.Invoice`. A type assertion compares the dynamic type exactly. Whichever of `T` and `*T` was put in comes out.

**`switch v := x.(type)` declares a new `v`.** Inside the `string` case, `v` was the string and could be changed; after the switch, `v` is `outer` again. Every clause gets its own variable, shadowing the outer one for the length of the clause — the [`shadow` analyzer ↗](https://pkg.go.dev/golang.org/x/tools/go/analysis/passes/shadow) exists for this, and is not among the checks `go vet` runs by default.

What the compiler can rule out before any of this runs — an assertion to a type that cannot satisfy the interface, an assertion on a non-interface, a duplicate case — is on the [compiler errors page](../interfaces_compiler_errors/README.md#impossible-type-assertion).

```go
// A type assertion x.(T) asks whether the dynamic type of x is T -- or, when
// T is an interface, whether that dynamic type has T's methods. The two-value
// form answers with ok; the one-value form panics with the runtime's
// "interface conversion" message. A type switch does the same over several
// cases: in a single-type case the bound variable has that type, in a case
// listing several types (or in default) it keeps the interface type, and the
// variable shadows any outer one of the same name.
//
//	go build type_switches_and_assertions_go.go && ./type_switches_and_assertions_go
package main

import (
	"errors"
	"fmt"
	"reflect"
)

type Order struct{ ID int }

type Invoice struct{ ID int }

func (i Invoice) String() string { return fmt.Sprintf("invoice %d", i.ID) }

// describe classifies a value with one type switch. staticType reports the
// type the compiler gave the bound variable x in that case.
func describe(v any) string {
	switch x := v.(type) {
	case nil:
		return "nil: no dynamic type at all"
	case int:
		return fmt.Sprintf("int %d            (x has static type %s)", x, staticType(&x))
	case int8, int16, int32, int64:
		return fmt.Sprintf("a sized int %v    (x has static type %s)", x, staticType(&x))
	case fmt.Stringer:
		return fmt.Sprintf("a Stringer: %q (x has static type %s)", x.String(), staticType(&x))
	case error:
		return "an error: " + x.Error()
	default:
		return fmt.Sprintf("something else: %T (x has static type %s)", x, staticType(&x))
	}
}

func staticType[T any](p *T) string { return reflect.TypeOf(p).Elem().String() }

func panicOf(f func()) (value any) {
	defer func() { value = recover() }()
	f()
	return "none"
}

func main() {
	for _, v := range []any{nil, 42, int64(42), Invoice{ID: 3}, errors.New("late"), Order{ID: 9}} {
		fmt.Println("describe:", describe(v))
	}

	var x any = "order-17"
	s, ok := x.(string)
	fmt.Printf("x.(string) two-value: %q, %t\n", s, ok)
	n, ok := x.(int)
	fmt.Printf("x.(int)    two-value: %d, %t (the zero value, and false)\n", n, ok)
	fmt.Println("x.(int)    one-value panics:", panicOf(func() { _ = x.(int) }))

	var nothing any
	fmt.Println("nil.(int)  one-value panics:", panicOf(func() { _ = nothing.(int) }))

	// Asserting to another interface checks the dynamic type's method set at run time.
	var order any = Order{ID: 9}
	_, ok = order.(fmt.Stringer)
	fmt.Println("Order as fmt.Stringer, two-value:", ok)
	fmt.Println("Order as fmt.Stringer, one-value panics:", panicOf(func() { _ = order.(fmt.Stringer) }))
	var str fmt.Stringer = Invoice{ID: 3}
	fmt.Println("fmt.Stringer holding Invoice, asserted to *Invoice, panics:", panicOf(func() { _ = str.(*Invoice) }))

	// switch v := x.(type) declares a new v for the switch; the outer v is untouched.
	v := "outer"
	switch v := x.(type) {
	case string:
		v += " (changed inside the switch)"
		fmt.Println("inside:  v =", v)
	}
	fmt.Println("outside: v =", v)
}
```

## What to do

- **Use the two-value form unless a wrong type is a bug you want to crash on.** `v, ok := x.(T)` costs nothing extra and turns a panic into a branch.
- **Assert to behaviour, not to a type, when behaviour is what you need.** `if f, ok := w.(interface{ Flush() error }); ok` works for every type that can flush, including ones written after yours; `w.(*bufio.Writer)` works for one.
- **For errors, use `errors.As`.** A wrapped error's dynamic type is the wrapper's; `err.(*ValidationError)` sees only the outermost layer, and [`errors.As` finds a type in the chain](../../12_Errors/errors_as_finds_a_type_in_the_chain/README.md) walks all of them.
- **Write `case nil` when nil can arrive**, so that it does not land in `default` as a nil interface.
- **Reach for a type switch last.** A function that switches over several concrete types is often a function that wanted an interface, or, when the types share operations rather than methods, a type parameter — [Constraints are type sets](../../09_Generics/constraints_are_type_sets/README.md).

## Practice

A ledger receives its entries as a `[]any`: `int` values are cents, `float64` values are dollars, `string` values are memos, `nil` marks an empty line, and `Invoice` values have a `String` method. Write `tally(entries []any)` with a single type switch that adds all the money up in cents (round the dollars), counts the memos and the nils, collects each Stringer's text, and records the `%T` of anything else; make `case nil` explicit and put the `fmt.Stringer` case after the concrete ones. Print the totals in a fixed order.

```go
// Kata: a ledger receives entries as []any -- int cents, float64 dollars,
// string memos, nil placeholders, and Invoice values that are Stringers.
// Write tally with one type switch that adds up the money in cents, counts
// the memos and the nils, collects the Stringers' text, and print the totals.
//
//	go build type_switches_and_assertions_kata_go.go && ./type_switches_and_assertions_kata_go
package main

import (
	"fmt"
	"math"
	"strings"
)

type Invoice struct{ ID int }

func (i Invoice) String() string { return fmt.Sprintf("invoice %d", i.ID) }

type Tally struct {
	Cents    int
	Memos    int
	Nils     int
	Stringer []string
	Unknown  []string
}

func tally(entries []any) Tally {
	var t Tally
	for _, e := range entries {
		switch v := e.(type) {
		case nil:
			t.Nils++
		case int:
			t.Cents += v
		case float64:
			t.Cents += int(math.Round(v * 100))
		case string:
			t.Memos++
		case fmt.Stringer:
			t.Stringer = append(t.Stringer, v.String())
		default:
			t.Unknown = append(t.Unknown, fmt.Sprintf("%T", v))
		}
	}
	return t
}

func main() {
	entries := []any{250, 12.5, "paid by card", nil, Invoice{ID: 7}, 100, "refund", nil, Invoice{ID: 8}, 0.05, []int{1}}
	t := tally(entries)
	fmt.Printf("cents:     %d\n", t.Cents)
	fmt.Printf("memos:     %d\n", t.Memos)
	fmt.Printf("nils:      %d\n", t.Nils)
	fmt.Printf("stringers: %s\n", strings.Join(t.Stringer, ", "))
	fmt.Printf("unknown:   %s\n", strings.Join(t.Unknown, ", "))
}
```

## In other languages

- The Rust library's [What an enum is ↗](https://masiarek.github.io/rust-learning-library/13_Enums/what_an_enum_is/index.html) — Rust's answer to "which of these types is it" is an `enum` and `match`, closed at compile time, so there is no `ok` and no panic; a trait object cannot be asked its concrete type unless it is [`Any` ↗](https://doc.rust-lang.org/std/any/trait.Any.html), whose `downcast_ref::<T>()` is the two-value assertion returning an `Option`.
- C++ `dynamic_cast<T*>` returns `nullptr` on failure and `dynamic_cast<T&>` throws `std::bad_cast` ([cppreference ↗](https://en.cppreference.com/w/cpp/language/dynamic_cast)) — the two-value and one-value forms, with a class hierarchy instead of a method set; Java's `instanceof` with a pattern variable ([Java 21 ↗](https://docs.oracle.com/en/java/javase/21/language/pattern-matching-instanceof.html)) binds the narrowed variable the way a one-type case does.
